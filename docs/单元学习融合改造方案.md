# 教学配置 · 学期×科目×课程表 整合改造方案

> 目标：把"学期配置、科目配置、课程表"整合成**一套统一的教学配置体系**，
> 配置好后，系统根据**孩子每天的上课安排**做分析——
> 今天上了什么课 → 该科现在学到第几单元 → 本单元知识点 → 本单元作业 → 掌握度。

---

## 一、核心思路：从"三个独立配置"到"一套教学配置"

### 1.1 原来的误区
我之前把"课程表"当成一个独立模块叠加。但学期、科目、课程表本质是**同一棵树的三个层次**：

```
教学配置（一个学年）
└── 学期（上学期 / 下学期）
    ├── 科目（该学期在学的科目：语文/数学/英语…）
    │   └── 单元（该科本学期的单元目录 + 知识点）
    └── 课程表（星期 × 节次 → 对应到科目）
```

### 1.2 整合后的关系
| 配置 | 内容 | 与谁关联 |
|---|---|---|
| 学期 | 开学/期中/期末日期、周数、当前学期标记 | 承载科目与课表 |
| 科目 | 该学期在学哪些科目 | 绑定到学期，下挂单元 |
| 单元目录 | 每科每单元标题 + 知识点列表 | 绑定到科目的学期 |
| 课程表 | 每天哪些节次上哪科 | 绑定到学期，指向科目 |

**核心衔接**：课程表里的"科目" 与 科目配置里的"科目" 是**同一个对象**，因此课表一格 = 某学期某科的某节课 → 可下钻到该科当前学习的单元。

## 二、整合后的配置入口（系统设置页）

把现有分散的配置整合为清晰的"教学"区域，数据统一存一套：

### 2.1 统一数据文件：`data/school.json`（替代零散的学期/科目/课表）
```json
{
  "schoolYear": "2026-2027",
  "currentSemesterId": "s1",
  "semesters": [
    {
      "id": "s1",
      "label": "上学期",
      "grade": "四年级",
      "term": "上",
      "start": "2026-09-01",
      "midterm": "2026-11-02",
      "end": "2027-01-25",
      "weekCount": 22,
      "subjects": [
        {
          "name": "语文",
          "version": "人教部编版",
          "color": "#F95D9F",
          "units": [
            { "id": "u1", "unit": "第一单元", "title": "自然之美",
              "lessons": ["1 观潮","2 走月亮","现代诗二首","4 繁星"],
              "knowledge": ["边读边想象画面","体会自然之美"] }
          ]
        }
      ],
      "timetable": {
        "periodCount": 6,
        "days": ["周一","周二","周三","周四","周五"],
        "grid": [
          { "day": 1, "period": 1, "subject": "语文" },
          { "day": 1, "period": 2, "subject": "数学" },
          { "day": 1, "period": 3, "subject": "英语" }
        ]
      }
    }
  ]
}
```
> 说明：`subjects` 里既含每科的单元目录，`timetable.grid` 引用同一套科目名。这样**科目、单元、课表天然绑定在同一学期下**，不再各自为政。

### 2.2 系统设置页整合为"教学配置"区
在设置页新增/整合一个 **"教学" 主区块（或 tab）**，内部按"学期 → 科目 → 单元 → 课表"四层组织：

1. **学期层**：选择/管理学期（开学、期中、期末、当前学期）
2. **科目层**：该学期在学哪些科目（勾选，颜色沿用 config.json）
3. **单元层**：选中科目后维护其单元目录（单元名、标题、知识点、课文/课时）
4. **课表层**：可视化网格（星期×节次），每格下拉选"该学期科目"

现有"科目 tab（config.json 全量科目）"保留为**科目库**（所有可能的科目+颜色），"教学配置"里的科目层从这个库选。

## 三、基于"每天上课安排"的分析（核心价值）

配置好教学配置后，系统即可做**上课驱动的分析**：

### 3.1 知识星球页 · 单元学习视图（整合课表）
```
┌─ 学期切换：上学期 / 下学期 ─────────────────┐
│  📅 本周课表（星期一~五 × 节次，科目色块）      │
│     | 周一 | 周二 | 周三 | 周四 | 周五        │
│  1节 | 语文 | 数学 | 语文 | ... | ...        │
│  2节 | 数学 | 英语 | ...   | ... | ...        │
│  ── 今天：周三 ──                           │
│  ◆ 今天有【语文】课 → 语文本周学到「第二单元」  │
│    · 知识点：提问策略                          │
│    · 本单元作业：3 项待完成 / 2 项已完成        │
└────────────────────────────────────────────┘
```

### 3.2 分析逻辑（上课 → 单元 → 作业 → 掌握度）
```
今天是 X 月 X 日
  → 由 school.json 定位：当前学期 + 当前周数
  → 由课表：今天有哪些科目的课
  → 对每个科目：该科在学期进度中当前学到第几单元
      → 该单元知识点
      → 该单元下挂的作业（完成率）
      → 该单元日常测验（如有）
      → 掌握度估算
```

### 3.3 产出洞察（给家长看）
- **今天要留意**：今天有语文课，语文「第二单元」作业还有 3 项没完成
- **本周节奏**：本周五节数学课，数学「大数读写」单元有测验
- **学习进度**：各科当前停留单元 vs 学期总单元，进度百分比

## 四、对现有功能的适配

| 现有功能 | 适配方式 |
|---|---|
| 校历（base tab 学期时间线） | 保留视觉，数据源改为 school.json 的 semesters |
| 科目 tab（config.json 科目库） | 保留为"科目库"，教学配置的科目层从中选 |
| 作业录入 | 弹出新增"所属科目→所属单元"下拉（随学期科目联动） |
| 成绩录入 | 新增"所属单元"（可选，日常测验可挂） |
| 能力分析 | 新增"按单元"视角，串联 知识点→作业→测验 |
| 首页学期进度 | 复用 school.json 的学期日期计算 |
