# 小宇宙系统优化设计方案

## 1. 概述

### 1.1 背景

当前系统有 5 个页面视图：首页（中心）、能量星球、知识星球、财富星球、记录小行星。其中"记录小行星"的功能与能量星球高度重叠——两者都提供 XP 记录能力。造成用户困惑和操作冗余。

同时，作业和财务条目本应是自动生成的，但记录小行星提供了手动录入入口，违背了设计原则。

### 1.2 核心决策

**去掉"记录小行星"页面**，将其手动打卡功能合并到能量星球（已具备"获得 XP"弹窗），知识星球负责作业管理，财富星球负责财务管理。

## 3. 系统设置关联（详细）

### 3.1 任务规则配置（`system-settings.html` 任务规则面板）

系统设置中定义 4 大分类共 23 条 XP 规则，各星球按规则类型消费：

| 分类 | 规则数 | 作业类规则 | 适用星球 | 触发方式 |
|------|--------|-----------|---------|---------|
| 学习成长 | 9 条 | 4 条（作业·日常/暑假/假期/家庭） | 知识星球 | 作业完成自动发放 |
| 兴趣爱好 | 2 条 | 0 条 | 能量星球 | 手动打卡 |
| 身体成长 | 4 条 | 0 条 | 能量星球 | 手动打卡 |
| 能力成长 | 8 条 | 0 条 | 能量星球 | 手动打卡 |

**规则匹配机制：**

```
系统设置 → 保存规则到 data-store
    → 能量星球"获得 XP"弹窗读取规则列表，作为下拉选项
    → 知识星球"作业完成"时按 name 匹配规则（如 "作业·日常作业"）
    → 匹配成功则自动发放对应 XP 值
    → 无匹配时使用默认映射表兜底
```

### 3.2 财务分类配置（`system-settings.html` 财务分类面板）

系统设置中定义 6 个收入分类和 3 个支出分类，以及 2 个账户：

```
财富星球：
    → 记账时读取财务分类作为下拉选项
    → 财务复盘时自动发放"财务能力分析"XP（5 XP）
    → 匹配规则：按 name="财务能力分析" 匹配能力成长分类
```

### 3.3 科目/能力模块配置（`system-settings.html` 科目配置面板）

```
知识星球：
    → 添加作业时读取科目列表作为选择器
    → 选择科目后动态加载对应能力模块复选框
    → 能力模块数据来自系统设置的 abilityModules
```

### 3.4 数据一致性保障

所有规则配置存储在 `DataStore` 中，各页面通过 `loadAppData()` 统一加载：

```
loadAppData()
    → cfg.config.xpRules      // 按分类组织的规则
    → cfg.config.xpRuleList   // 扁平化规则列表（用于快速查找）
    → cfg.config.abilityModules // 能力模块
    → cfg.config.subjects     // 科目配置
```

## 4. 积分计算逻辑（详细）

### 4.1 积分来源分类

系统积分（XP）分为三大星球板块，由 `getPlanetXp()` 函数按任务名称前缀匹配：

```javascript
function getPlanetXp(verifiedXpRecords) {
  // 结果：{ energy: 0, knowledge: 0, finance: 0 }
  verifiedXpRecords.forEach(r => {
    const name = r.taskName || r.title || "";
    if (name.indexOf("作业") === 0) → knowledge（知识星球）
    else if (name.indexOf("财务") >= 0) → finance（财富星球）
    else → energy（能量星球）
  });
}
```

### 4.2 积分数据流

```
┌─────────────────────────────────────────────────────────────────────┐
│                         积分数据流全景                               │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  [手动打卡]                                                         │
│  能量星球"获得 XP"弹窗                                               │
│    → 选择规则（从系统设置加载）→ 填写备注 → 提交                     │
│    → DataStore.addXpRecord({taskName, xp, description, status, ...}) │
│    → 状态：pending（待确认）                                         │
│    → 首页/能量星球刷新 → 待确认计数 +1                               │
│                                                                     │

│  [作业完成自动发放]                                                 │
│  知识星球 → 作业标记为"完成"                                        │
│    → grantHomeworkCompletionXp(item, cfg)                           │
│    → 从系统设置规则中查找 "作业·{homeworkType}"                     │
│    → 匹配成功使用规则 XP 值，否则使用默认映射表                      │
│      {日常作业:2, 暑假作业:2, 假期作业:3, 家庭作业:4, ...}          │
│    → DataStore.addXpRecord({taskName:"作业·{type}", ...})           │
│    → 状态：verified（自动通过）                                      │
│    → 归属知识星球积分                                               │
│                                                                     │
│  [财务复盘自动发放]                                                 │
│  财富星球 → 完成财务对账                                           │
│    → 匹配规则"财务能力分析"（能力成长分类，5 XP）                   │
│    → DataStore.addXpRecord({taskName:"财务能力分析", ...})          │
│    → 状态：verified（自动通过）                                      │
│    → 归属财富星球积分                                               │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.3 审核流程

```
手动打卡记录 → status: "pending"
    → 首页/能量星球显示"待确认 N 条"
    → 家长审批 → 通过 → status: "verified" → 计入总 XP
               → 退回 → status: "returned" → 不计数

自动发放记录 → status: "verified"（直接通过，无需审批）
    · 作业完成 XP
    · 财务复盘 XP
```

### 4.4 等级计算

```
总 XP（所有 verified 记录之和）→ getLevelProgress()
    → 匹配等级阈值（levels 数组）
    → 计算当前等级、下一级、进度百分比
    → 首页展示成长之路时间轴
```

### 4.5 连续活跃天数

```
getCheckInStreak() 计算连续活跃天数：
    → 统计所有已通过 XP 记录，按日期去重
    → 从今天（或昨天）起往前数连续有记录的天数
    → 遇断档即停
    → 能量星球顶部显示"连续活跃 N 天"
```

## 5. 改造方案

### 5.1 移除"记录小行星"页面

**涉及文件：** `index.html`

**改动内容：**

1. 删除 `#view-data-entry` 整个 `<section>`（含 XP 表单、学习表单、财务表单）
2. 删除底部导航栏中 `data-page="data-entry"` 的 tab 项
3. 删除 `switchView()` 中 `data-entry` 的处理逻辑
4. 删除 `initDataEntry()` 和 `initDataEntryGuarded()` 函数
5. 删除 `data-entry.js` 模块中所有相关函数（`deLoadAbilityModules`、`deRenderSubjectGroups`、`deGetSubjectModules` 等）
6. 删除 `boot()` 中 `data-entry` 的启动路由

### 5.2 能量星球 — 完善手动打卡能力

**当前状态：** 能量星球已有 `openXpModal()` 弹窗（含规则选择、备注、XP 值、分类、提交），功能完整。

**需要确认/完善：**
- 确保 `openXpModal()` 中的规则下拉列表（`populateXpTaskSelectPage()`）正确过滤掉作业类规则（因为这些应该在知识星球自动发放）
- 规则过滤逻辑：排除 `name` 以"作业·"开头的规则

### 5.3 知识星球 — 作业管理

**当前状态：** 知识星球已有完整的作业列表渲染，作业完成时自动调用 `grantHomeworkCompletionXp()` 发放 XP。

**数据流：**
```
添加作业（通过飞书多维表格或 API）
    → 存入 study.json
    → 首页今日任务自动拉取
    → 标记完成 → grantHomeworkCompletionXp()
    → 匹配系统设置规则 → 自动发放 XP
```

**系统设置关联：** `grantHomeworkCompletionXp()` 从 `cfg.config.xpRuleList` 中按 `name === "作业·{homeworkType}"` 匹配规则，获取 XP 值。

### 5.4 财富星球 — 财务管理

**不变。** 已有完整记账功能，记账时使用系统设置的财务分类，财务复盘时自动发放 XP。

### 5.5 首页（中心）— 调整

**变动：**
- 底部导航栏去掉"记录"tab
- 若需要，可在能量星球区域增加快速入口提示

## 7. 实现要点

### 7.1 规则过滤

在能量星球 `populateXpTaskSelectPage()` 中，加载规则列表时需过滤掉作业类规则：

```javascript
// 过滤逻辑
const rules = (cfg.config?.xpRuleList || [])
  .filter(r => !r.name.startsWith("作业·"));  // 排除作业类规则
```

### 7.2 数据加载

所有页面统一通过 `loadAppData()` 加载数据，确保系统设置变更后各星球实时同步：

```javascript
const cfg = await loadAppData();
// cfg.config.xpRules — 按分类组织
// cfg.config.xpRuleList — 扁平列表
// cfg.config.abilityModules — 能力模块
```

### 7.3 删除安全

删除 `data-entry` 相关代码时，需确保不误删其他模块共享的全局函数（如 `getPlanetXp`、`checkInDaily` 等）。
