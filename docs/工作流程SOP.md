# 代码改动交付流程 SOP（本地优先版）

> 本流程规范「本地开发 → 本地测试 → 用户确认 → 上线推送」的完整链路。
> **核心原则：所有功能新增和修改都在本地进行，直到用户测试通过后才允许上传；上传时自动切换数据调用方式。**

---

## 一、核心原则

**"推给你"绝对不等于"推送到 GitHub 线上"。**

- `推给你` = 在本地启动测试服务器，把预览链接发你确认效果
- `推送到 GitHub / 上线` = 你明确确认 OK 之后，才允许执行

**任何未经你确认的线上推送，都是违规操作。**

**数据调用方式（关键）：**
- 本地测试：数据读写走本地 `data/` 目录（`node scripts/local-server.js` 启动，无需 Token）
- 线上部署：数据读写自动切换为 GitHub 模式（读取走 GitHub raw，写入走 GitHub API 需 Token）
- 切换是**自动**的：前端通过 `/api/ping` 探测当前环境，本地服务器有该接口 → 本地模式；线上没有 → GitHub 模式。**无需手动改代码。**

---

## 二、完整工作流程

### 第 1 步：本地开发
- 所有改动只在本地工作区 `/workspace/github-deploy` 进行
- 每完成一个功能点，先做语法校验（HTML/JS 语法、JSON 合法性）

### 第 2 步：本地测试（「推给你」）
- 启动本地测试服务器：`node scripts/local-server.js 8090`
- 浏览器打开 `http://localhost:8090/index.html`（若之前打开过，加 `?nocache=xxx` 强制刷新）
- 本地模式下所有数据读写走本地 `data/` 目录，**无需 GitHub Token**
- 把本地预览链接发给你，并说明本次改了什么、让你重点看哪里
- 若你反馈链接打不开/缓存，先排查本地服务状态，必要时请你强制刷新

### 第 3 步：确认修改（OK / 不满意）
- 等你预览并给出反馈
- 若 `OK` → 进入第 4 步
- 若 `不满意` → 回到第 1 步修改，循环直到你确认

### 第 4 步：上线推送（仅在你确认后）
- 必须在第 3 步你明确说"可以/确认/上线/推送"之后
- 推荐使用一键上传脚本：`bash scripts/upload.sh "本次改动说明"`
- 脚本会自动：检查改动 → 确认 → commit → push → 验证线上版本
- 推送前先 `git status` 确认改动范围，推送后验证线上版本

### 第 5 步：验证线上
- 用 `git fetch` + `git rev-parse` 确认线上版本与你确认的提交一致
- 线上访问时数据自动切换为 GitHub 模式（读取走 raw，无需 Token；写入走 API 需 Token）

---

## 三、本地测试服务器说明

| 项目 | 说明 |
|------|------|
| 启动命令 | `node scripts/local-server.js 8090`（端口可改） |
| 访问地址 | `http://localhost:8090/index.html` |
| 数据读取 | 本地 `data/` 目录（相对路径） |
| 数据写入 | `POST /api/write` → 写入本地 `data/` 目录 |
| Token 要求 | 完全不需要 |
| 探测接口 | `/api/ping` 返回 `{"ok":true,"mode":"local"}` |
| 停止方式 | Ctrl+C |

> 注意：本地测试写入的数据会直接修改 `data/` 目录下的 JSON 文件。测试完成后如需恢复，用 `git checkout -- data/` 还原。

---

## 四、回滚规则（如误推送）

当发生误推送时：
1. 先定位你要求的"旧版本"对应的 commit
2. 通过 `git revert` 或 `git reset` + `git push --force` 恢复线上到该版本
3. 恢复后必须用 `git rev-parse origin/<branch>` 确认线上版本号已回到目标 commit
4. **恢复好之后，要明确告知你已经恢复，并说明恢复到了哪个版本**

---

## 五、关键约定（避免误操作）

| 触发词 | 正确动作 | 禁止动作 |
|--------|----------|----------|
| "推给你 / 发我看看 / 看一下" | 启动本地测试服务器，发预览链接 | 推送到 GitHub |
| "上线 / 推送 / 确认 / 可以" | 执行 `scripts/upload.sh` 推送到 GitHub | 提前推送 |
| "恢复到旧版本 / 恢复代码" | 恢复 GitHub 线上 + 本地 | 只改本地不线上 |
| "我看看效果 / 改一下" | 本地改 + 本地测试 | 直接 commit/push |

---

## 六、交付前自检清单

- [ ] 本地语法校验通过（HTML/JS/JSON）
- [ ] 本地测试服务器启动正常（`node scripts/local-server.js`）
- [ ] 本地预览能正常打开，功能符合需求，数据读写走本地 `data/`
- [ ] 已把改动内容和预览链接发给用户
- [ ] 已获得用户明确确认（OK）
- [ ] 确认后才执行 `scripts/upload.sh` 上传
- [ ] 推送后验证线上版本号正确，数据自动切换为 GitHub 模式
