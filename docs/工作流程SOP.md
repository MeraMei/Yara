# 代码改动交付流程 SOP（本地优先版）

> 本流程规范「本地开发 → 本地测试 → 用户确认 → 上线推送」的完整链路。
> **核心原则：所有功能新增和修改都在本地进行，直到用户测试通过后才允许上传；上传时自动切换数据调用方式。**

---

## 一、核心原则

**"推给你"绝对不等于"推送到 GitHub 线上"。**

- `推给你` = 在本地启动测试服务器，把预览链接发你确认效果
- `推送到 GitHub / 上线` = 你明确确认 OK 之后，才允许执行

**任何未经你确认的线上推送，都是违规操作。**

**数据调用方式（关键）：**
- 本地测试：数据读写走本地 `data/` 目录（`node scripts/local-server.js` 启动，无需 Token）
- 线上部署：数据读写自动切换为 GitHub 模式（读取走 GitHub raw，写入走 GitHub API 需 Token）
- 切换是**自动**的：前端通过 `/api/ping` 探测当前环境，本地服务器有该接口 → 本地模式；线上没有 → GitHub 模式。**无需手动改代码。**

---

## 二、完整工作流程

### 第 1 步：本地开发
- 所有改动只在本地工作区 `/workspace/github-deploy` 进行
- 每完成一个功能点，先做语法校验（HTML/JS 语法、JSON 合法性）

### 第 2 步：本地测试（「推给你」）
- 启动本地测试服务器：`node scripts/local-server.js 8090`
- 浏览器打开 `http://localhost:8090/index.html`（若之前打开过，加 `?nocache=xxx` 强制刷新）
- 本地模式下所有数据读写走本地 `data/` 目录，**无需 GitHub Token**
- 把本地预览链接发给你，并说明本次改了什么、让你重点看哪里
- 若你反馈链接打不开/缓存，先排查本地服务状态，必要时请你强制刷新

### 第 3 步：确认修改（OK / 不满意）
- 等你预览并给出反馈
- 若 `OK` → 进入第 4 步
- 若 `不满意` → 回到第 1 步修改，循环直到你确认

### 第 4 步：上线推送（仅在你确认后）
- 必须在第 3 步你明确说"可以/确认/上线/推送"之后
- 推荐使用一键上传脚本。脚本内置**两道闸**，从机制上锁死"未经你确认就擅自推送 GitHub"：
  - **第一道·方向闸**：脚本默认安全模式，只做本地体检/提交前检查，**绝不 push**。必须显式加 `--push` 才会进入推送环节。
  - **第二道·授权闸**：即使加了 `--push`，还必须带 `--auth <授权词>`。授权词取自你在对话里明确说出的"可以上传 / 确认上传 / 上传到GitHub"等信号，且必须含授权语义，否则脚本直接 `exit 1` 拒绝推送。
- 上传命令（按需组合）：
  - 本地体检（不推送）：`bash scripts/upload.sh "说明"`（安全模式）
  - 推送线上（需你已授权）：`bash scripts/upload.sh --push --auth "确认上传" "说明"`
  - 若同时要更新线上数据库（data/）：加 `--with-data`：`bash scripts/upload.sh --with-data --push --auth "确认上传" "说明"`
- 推送前自动跑提交前体检（`pre-commit-check.py`），有必须修复项则阻断；推送后验证线上版本号

### 第 5 步：验证线上
- 用 `git fetch` + `git rev-parse` 确认线上版本与你确认的提交一致
- 线上访问时数据自动切换为 GitHub 模式（读取走 raw，无需 Token；写入走 API 需 Token）

## 三、本地测试服务器说明

| 项目 | 说明 |
|------|------|
| 启动命令 | `node scripts/local-server.js 8090`（端口可改） |
| 访问地址 | `http://localhost:8090/index.html` |
| 数据读取 | 本地 `data/` 目录（相对路径） |
| 数据写入 | `POST /api/write` → 写入本地 `data/` 目录 |
| Token 要求 | 完全不需要 |
| 探测接口 | `/api/ping` 返回 `{"ok":true,"mode":"local"}` |
| 停止方式 | Ctrl+C |

> 注意：本地测试写入的数据会直接修改 `data/` 目录下的 JSON 文件。测试完成后如需恢复，用 `git checkout -- data/` 还原。

---

## 四、回滚规则（如误推送）

当发生误推送时：
1. 先定位你要求的"旧版本"对应的 commit
2. 通过 `git revert` 或 `git reset` + `git push --force` 恢复线上到该版本
3. 恢复后必须用 `git rev-parse origin/<branch>` 确认线上版本号已回到目标 commit
4. **恢复好之后，要明确告知你已经恢复，并说明恢复到了哪个版本**

---

## 五、关键约定（避免误操作）

| 触发词 | 正确动作 | 禁止动作 |
|--------|----------|----------|
| "推给你 / 发我看看 / 看一下" | 启动本地测试服务器，发预览链接 | 推送到 GitHub |
| "上线 / 推送 / 确认 / 可以" | 获得你的授权词后，执行 `bash scripts/upload.sh --push --auth "授权词"` 推送 GitHub | 未带 `--auth` 就 hard 推送 |
| "恢复到旧版本 / 恢复代码" | 恢复 GitHub 线上 + 本地 | 只改本地不线上 |
| "我看看效果 / 改一下" | 本地改 + 本地测试 | 直接 commit/push |

> 上传机制：`upload.sh` 默认安全模式，未显式加 `--push` 绝不推送；加 `--push` 但无 `--auth` 授权词也会被授权闸拒绝。**未拿到你明确的"上传/确认"信号，脚本物理上无法推送线上。**

## 六、交付前自检清单

- [ ] 本地语法校验通过（HTML/JS/JSON）
- [ ] 本地测试服务器启动正常（`node scripts/local-server.js`）
- [ ] 本地预览能正常打开，功能符合需求，数据读写走本地 `data/`
- [ ] 已把改动内容和预览链接发给用户
- [ ] 已获得用户明确确认（OK），且拿到用户授权词
- [ ] 确认后才执行 `bash scripts/upload.sh --push --auth "授权词"` 上传（本地无 `--push` 仅体检不推送）
- [ ] 推送后验证线上版本号正确，数据自动切换为 GitHub 模式

## 七、上传前检查清单（11 项）

> 所有检查分为【每次必跑】和【按场景跑】两层，由 `scripts/upload.sh` 自动执行，不依赖 AI 记忆或自觉。

### 7.1 每次必跑（5 项 · 骨架）

| # | 检查 | 载体 | 作用 |
|---|------|------|------|
| 1 | 语法校验 | `scenario-check.py` S1 | 改动的 HTML/JS/PY/SH 语法正确，避免低级报错 |
| 2 | Git 状态检查 | `upload.sh` 步骤1 | 确认分支、远程 host、改动范围无异常 |
| 3 | 用户确认（授权闸） | `upload.sh` 方向闸+授权闸 | 未显式 `--push` 绝不推送；无条件未带授权词拒绝 |
| 4 | data 隔离 | `upload.sh` git add 逻辑 | 默认跳过 `data/`，仅加 `--with-data` 才更新线上数据库 |
| 5 | SHA 校验 | `upload.sh` 步骤4/4 | 推送后核对本地/线上 commit 一致 |

### 7.2 按场景跑（6 项）

| # | 检查 | 触发场景 | 作用 |
|---|------|----------|------|
| 6 | 全平台体检 | `pre-commit-check.py`（script 每次调用） | 结构/交互/JSON/CSS 变量/token key 闭环/仓库卫生 |
| 7 | 移动端 UI 抽查 | 有 `.html/.css/.js` 改动 | 提醒人工在手机/窄屏抽查移动端显示 |
| 8 | 空文件检测 | `scenario-check.py` S2 | 0 字节文件禁止上传 |
| 9 | 编码检测 | `scenario-check.py` S3 | UTF-8 可解码、无 BOM |
| 10 | 敏感信息扫描 | `scenario-check.py` S4 | 代码里不得混入 token/私钥（泄露即自动阻断） |
| 11 | data JSON 一致性 | 内含在 `pre-commit-check.py` C1-C3 | data JSON 可解析、字段完整 |

### 7.3 敏感信息规则（上线硬约束）

- 任何 token / 私钥不得提交进仓库；`scenario-check.py` 会在上传前扫描并**自动阻断**。
- `upload.sh` 打印 git 信息时**只显示远程 host**，绝不输出完整 remote URL（其内嵌 token）。
- 若 remote 里已写入 token，请尽快更换，并改用不经 URL 传 Token 的方式。
